# Screenshots

Generated by `shots/ModDbShots.cs`, not hand-taken, so the set can be reproduced after a
visual change. **The images themselves are not tracked** — only what makes them. Run:

```bash
bash scripts/make-shots.sh              # dizzyd@vsclient.home by default
```

| | |
|---|---|
| `01-molten-crucible.png` | the hero shot: a crucible of molten copper sitting in a lit forge |
| `02-crucible-window.png` | the window, with a blend that works and what it will make |
| `03-wrong-ratio.png` | the window telling you the ratio it wants instead |
| `04-heat-states.png` | cold, hot and ready side by side at dusk, which is the whole readout at a distance |
| `05-melt-where-you-smith.png` | crucible, anvil and mold at one fire |

`02` and `03` are 1920x909 rather than 1690x909: the crucible window is anchored to a screen
edge by `GetFreePos`, so taking 115px off the sides clips it mid-sentence.

`07-icon-source.png` is not part of the set; it is cropped square and resized to
`crucibulum/modicon.png` at 480x480. That icon is a build input — CakeBuild copies it into the
release zip when it is there — so **a zip built from a fresh clone has no icon until this has
been run once**. The build does not fail without it. Two things have to be kept out of an icon that are fine in
a gallery shot:

- **The crosshair.** It is drawn by the client from `gui/target.png`, not by a dialog, so it
  cannot be closed — but it disappears while a GUI has the mouse ungrabbed. The icon shot opens
  the crucible window and leaves it open, off to the side of the square crop.
- **The block selection outline**, which is drawn on whatever the player is looking at. After
  opening the window the aim is moved off the forge, which keeps the outline away without
  closing anything.

Four things the shots need that a normal test run does not:

- **Particles and a real window.** vstestkit's client template turns particles off and runs at
  960x600 for deterministic visual baselines, so a stock run photographs no smoke in a small
  window. `make-shots.sh` swaps the template for the boot and puts it straight back — the
  template lives inside the slot's own checkout, so no other tenant on the box sees it, and it
  is only read at boot anyway. It then asserts the window really came up at 1920x1080.
- **Not shadows.** Asking for `shadowMapQuality` on this headless GL setup crashes the client at
  startup with *FBO ShadowmapFar: One or more attachment points are not framebuffer attachment
  complete*. That crash is worth failing loudly on: swallow it and `run.sh` simply boots its own
  session with the restored template, and you get small, particle-free shots that look fine
  until you open them.
- **The HUD.** `ICoreClientAPI.HideGuis` is read-only, but the minimap, block tooltip, hotbar
  and stat bars are all `GuiDialog`s and close on request. The hotbar and stat bars reopen
  themselves regardless, so the frames are cropped from 1920x1080 to 1690x909 to cut them off.

  There is no shot of the block info readout, though it was tried. `HudElementBlockAndEntityInfo`
  does not come back once closed — not by re-aiming afterwards, and not with `immersiveFpMode`
  left off — so the frame comes back showing a forge and no text. The window shots carry the same
  information, so it was dropped rather than chased further.
- **The seraph's hand.** Ordinary first person floats it in the corner of every frame;
  `immersiveFpMode` renders the body from the eyes instead and keeps it out.
- **Fog.** Distance haze washes the horizon out. It comes from the ambient manager rather than
  a render setting, so it is overridden with an `AmbientModifier` at full weight.

`VSTK_SHOT_DIR` is exported for the **boot**, not for `run.sh`. It is read inside the game
process, and `run.sh` reuses whatever session is already up — set it on `run.sh` and the game
never sees it, the shots land in the fallback `/tmp`, and the fetch quietly finds nothing.

Plots sit `Plots.Spacing` (48) apart, so a plot that size touches its neighbour and the previous
scene's blocks appear just past the boundary. Every scene clears well past the plot edge.
